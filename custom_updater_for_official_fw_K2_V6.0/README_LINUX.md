# Інструкція з прошивки тестера WITRN K2 у Linux

Ця інструкція описує процес оновлення та резервного копіювання прошивки USB-тестера **WITRN K2** в операційних системах Linux без використання Windows.

---

## Швидкі скрипти автоматизації

У директорії створено готові скрипти для роботи в один клік:

| Скрипт | Опис | Приклад виклику |
|---|---|---|
| [`probe.sh`](file:///home/air/Downloads/K2_V6.0/probe.sh) | Перевірка зв'язку з тестером у режимі DFU | `./probe.sh` |
| [`backup.sh`](file:///home/air/Downloads/K2_V6.0/backup.sh) | Зняття повної резервної копії пам'яті (2 проходи) | `./backup.sh` |
| [`flash.sh`](file:///home/air/Downloads/K2_V6.0/flash.sh) | Прошивка тестера (за замовчуванням `K2_APP_6.0.k2`) | `./flash.sh [файл.k2]` |
| [`inspect.sh`](file:///home/air/Downloads/K2_V6.0/inspect.sh) | Перегляд інформації та валідація файлу `.k2` | `./inspect.sh [файл.k2]` |

## 1. Підготовка оточення

Для взаємодії з USB HID пристроєм потрібен Python та бібліотека `hidapi`.

1. Створіть віртуальне оточення та встановіть бібліотеку:
```bash
python3 -m venv .venv
.venv/bin/pip install hidapi
```
*(Або встановіть системний пакет у вашому дистрибутиві, наприклад на Arch Linux: `sudo pacman -S python-hidapi`)*

У каталозі `tools/` цієї директорії вже збережено утиліту `k2_updater.py` та бібліотеку протоколу `k2up`.

---

## 2. Підключення тестера в режимі DFU

1. **Відключіть** тестер від будь-яких джерел живлення та портів.
2. Підготуйте кабель USB (Type-C з лініями даних D+/D-). Кабель має бути підключений до порту **CC1** тестера (порт для зв'язку з ПК / DFU / HID).
3. **Затисніть і утримуйте кнопку `-`** (мінус / DFU) на корпусі тестера.
4. Не відпускаючи кнопку, підключіть кабель до комп'ютера.
5. На екрані тестера з'явиться напис **DFU**. Після цього кнопку можна відпустити.

Перевірити виявлення пристрою в системі:
```bash
lsusb | grep 0716:5060
```
Має з'явитися рядок на зразок:
`Bus 003 Device 022: ID 0716:5060 WITRN WITRN.K2`

---

## 3. Перевірка зв'язку з пристроєм (Probe)

Для безпечної перевірки зв'язку без зміни пам'яті тестера:

```bash
.venv/bin/python tools/k2_updater.py probe --dfu
```

Утиліта виконає handshake та виведе інформацію:
- Підтвердження моделі (`confirmed_k2: true`)
- Дату та версію bootloader'а
- Поточну версію прошивки тестера

---

## 4. Створення резервної копії (Backup)

Перед прошивкою рекомендується зняти повний бекап:

```bash
.venv/bin/python tools/k2_updater.py backup --dfu
```

- Пам'ять зчитується у **два незалежні проходи** для гарантії повної цілісності.
- Дамп зберігається в підкаталозі `k2_backups/<дата_час>/`.
- Створюється файл швидкого відновлення `K2_RECOVERY_<версія>.k2`, який у разі потреби можна прошити назад.

---

## 5. Прошивка файлу оновлення (.k2)

1. Перевірка файлу прошивки (offline inspect):
```bash
.venv/bin/python tools/k2_updater.py inspect K2_APP_6.0.k2
```

2. Симуляція оновлення в пам'яті (dry-run, пристрій не чіпається):
```bash
.venv/bin/python tools/k2_updater.py dry-run K2_APP_6.0.k2
```

3. **Запис прошивки в тестер:**
```bash
.venv/bin/python tools/k2_updater.py flash K2_APP_6.0.k2 --dfu --yes
```

У процесі виконується:
- `[erase]` — очищення необхідних секторів flash-пам'яті (100%)
- `[write]` — передача блоків нової прошивки (100%)
- `[verify]` — зворотне зчитування та побайтова верифікація (100%)
- `[commit]` & `[exit]` — запис валідаційного маркеру запуску та перезавантаження тестера в звичайний режим.
